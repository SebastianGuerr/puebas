## Definición exacta de cada métrica

Es la referencia para todas las etapas siguientes (E0.5, E3, E4, E5); cualquier
ambigüedad debe resolverse leyendo esta sección, no el código.

### Tokenización
`TOKEN_RE = [^\W\d_]+` (Unicode) sobre el texto en minúscula. Se conservan tildes y la
eñe; se excluyen dígitos y separadores. Es el mismo criterio que ya usa
`evaluacion/referencia._tokens` y `evaluacion/pares.py`, sin plegar acentos: una
restauración de tilde (`medico` → `médico`) es una corrección real y debe poder
evaluarse como tal.

### Alineación (`mapa_cambios`)
Para una nota con tokens originales `orig` y una segunda versión `otros`
(`texto_correcto` o `texto_corregido`), `difflib.SequenceMatcher(a=orig, b=otros,
autojunk=False).get_opcodes()` da una lista de tramos `(tag, i1, i2, j1, j2)`. Se
construyen dos listas paralelas a `orig`, de su mismo largo:

- `cambiado[i]` — `True` si el token `i` de `orig` cae dentro de un tramo `replace` o
  `delete` (cualquier tramo no `equal`).
- `forma[i]` — el texto que le corresponde: el propio token si el tramo es `equal`; si
  no, la unión con espacios de `otros[j1:j2]`, **repetida en cada índice del tramo**
  cuando el reemplazo cubre varios tokens de `orig` a la vez (bloques de largo
  distinto entre `orig` y `otros`). Un `delete` puro dentro dels bloque asigna `forma
  = ""` (la "forma correcta" es que el token desaparezca).

Se aplica dos veces por nota, con la misma función: `mapa_cambios(orig,
texto_correcto)` da `(gold_cambiado, gold_forma)`; `mapa_cambios(orig,
texto_corregido)` da `(sistema_cambiado, sistema_forma)`. `gold_forma[i]` es, por
definición, "lo que el token `i` debería ser" tanto si el gold lo cambia como si no
(en ese caso es el propio token original).

**Limitación documentada, deliberada:** un tramo `insert` tiene `i1 == i2`
(`range(i1, i2)` vacío), así que una palabra que el gold *agrega* sin que exista nada
que corregir en el original no marca ningún índice de `orig`. La nota 4 y la 16 del
caso de prueba (más abajo) son exactamente ese caso: el gold añade "irradiado a
brazo" / "sin fiebre" y el sistema, que no reescribe, queda invisible para
`precision_deteccion`/`cobertura_deteccion`/`precision_correccion`/`cobertura_correccion`
en esos tokens — **pero sí** se refleja en CER/WER, que comparan las cadenas
completas. Es una limitación consciente: el enunciado del ítem define detección y
corrección sobre "tokens que el gold cambia" y una inserción no tiene token original
que cambiar. Si en E3–E5 aparecen muchas notas donde el gold agrega motivo completo
ausente, esta limitación debe revisarse (candidato para E6 o para un ítem nuevo).

### Detección
Por cada índice `i` de `orig` de cada nota evaluada (con fila correspondiente en el
CSV del sistema):

- `tp_det += 1` si `gold_cambiado[i] and sistema_cambiado[i]`.
- `fp_det += 1` si `sistema_cambiado[i] and not gold_cambiado[i]`.
- `fn_det += 1` si `gold_cambiado[i] and not sistema_cambiado[i]`.

```
precision_deteccion = tp_det / (tp_det + fp_det)
cobertura_deteccion = tp_det / (tp_det + fn_det)
```

Agregación: se suman los conteos de **todas** las notas evaluadas y se calcula un
único cociente al final (micro-promedio sobre tokens, no promedio de razones por
nota). Se eligió así porque una nota de 4 tokens y una de 40 no deben pesar igual en
la cifra global, y porque coincide con la lectura de `tasa_intervencion`.

### Corrección
Para cada índice `i`, `correccion_ok = sistema_cambiado[i] and (sistema_forma[i] ==
gold_forma[i])` (comparación de cadenas en minúscula, tildes incluidas, sin más
normalización).

- `tp_cor += 1` si `correccion_ok`.
- `fp_cor += 1` si `sistema_cambiado[i] and not correccion_ok` (el sistema tocó el
  token y no acertó la forma exacta: incluye "eligió mal" y "cambió algo que estaba
  bien").
- `fn_cor += 1` si `gold_cambiado[i] and not correccion_ok` (el gold quería un cambio
  y no se logró: incluye omisión total y corrección a una forma distinta).

Un mismo índice puede sumar a `fp_cor` y a `fn_cor` a la vez (el sistema tocó un token
que el gold también quería tocar, pero con la forma equivocada): es intencional,
simétrico a la definición estándar de precisión/cobertura en GEC (ERRANT/M2).

```
precision_correccion = tp_cor / (tp_cor + fp_cor)   # = tp_cor / total de tokens tocados por el sistema
cobertura_correccion = tp_cor / (tp_cor + fn_cor)   # = tp_cor / total de tokens que el gold cambia
F0.5 = (1 + 0.5²) · P·R / (0.5² · P + R),  con P = precision_correccion, R = cobertura_correccion
     = 1,25 · P·R / (0,25·P + R)
```
β = 0,5 pondera la precisión el doble que la cobertura (estándar CoNLL-2014/BEA-19,
`INVESTIGACION.md` §3.6): una corrección de más cuesta más que una omisión.

### `tasa_intervencion`
```
interv_den += 1 si not gold_cambiado[i]     # tokens que el gold deja igual
interv_num += 1 si (not gold_cambiado[i]) and sistema_cambiado[i]   # y el sistema toca
tasa_intervencion = interv_num / interv_den
```
Micro-promedio, igual que detección. Es la misma idea que
`tasa_intervencion_texto_limpio` de `INVESTIGACION.md` §3.6/`PLAN.md` E2.2, medida
aquí sobre los tokens que el propio gold considera correctos en vez de sobre un
corpus léxico aparte: cuando E2.3 exista, el uso previsto es correr este mismo módulo
con `texto_correcto == texto_original` sobre el conjunto limpio, para obtener la
lectura "sobre texto limpio" definida en el plan sin duplicar código.

### CER y WER (control)
Solo se calculan para notas con fila en el CSV del sistema.
- **CER**: distancia de Levenshtein clásica (inserción/borrado/sustitución, sin
  transposición) entre `texto_corregido` y `texto_correcto`, ambos recortados y en
  minúscula, **a nivel de carácter** (incluye espacios), dividida por `len(texto_correcto)`.
- **WER**: la misma distancia a nivel de **token** (la lista de `tokenizar()`),
  dividida por el número de tokens de `texto_correcto`.
- Agregación: `sum(distancias) / sum(longitudes_de_referencia)` sobre todas las notas
  evaluadas (micro-promedio, no promedio de razones por nota), consistente con el
  resto del módulo.
- Es un control, no una métrica de aceptación: `INVESTIGACION.md` §3.6 señala
  explícitamente que `volcamiento → tocamiento` tiene CER mínimo y es un error
  crítico (nota 8 del caso de prueba). No se usa para decidir si un experimento
  mejora.

### `acuerdo_motivo`
Para cada nota con `motivo_span` (gold) y `texto_embedding` (sistema) no ambos
vacíos: `Jaccard(tokenizar(motivo_span), tokenizar(texto_embedding)) = |A∩B| / |A∪B|`.
El agregado final es la **media aritmética** de esos valores por nota (macro-promedio,
a diferencia de detección/corrección/CER/WER): el Jaccard ya es una razón acotada en
`[0,1]` por nota, y promediar razones tiene sentido aquí porque no hay un
"denominador natural" compartible entre notas como sí lo hay en tokens tocados.
Notas con ambos campos vacíos se excluyen del promedio (indefinido, no cero).

### `version_corrector`
Se lee con una expresión regular sobre `NLP/procesar.py`
(`VERSION_CORRECTOR\s*=\s*"([^"]+)"`), **sin importar el módulo**. Se comprobó
explícitamente: importar `NLP.procesar` no conecta a la base de datos (los imports de
`nucleo.conexion_bd` están diferidos dentro de funciones, confirmado leyendo el grafo
de `ARQUITECTURA.md` §3 y el propio archivo) pero tarda 5,44 s (carga de spaCy,
`language_tool_python`, sklearn vía `reduccion/frases.py`, aunque los objetos pesados
de spaCy/LanguageTool en sí son perezosos y no se instancian al importar). Ese costo
se pagaría en cada invocación de `metricas.py`, que según el plan se usa en todas las
bitácoras de E3 a E5 — muchas veces por sesión, en una máquina con poca RAM libre y
sin GPU. Leer con regex evita el costo y evita sumar la huella de memoria de esas
librerías a la del job de reparación que ya corre en paralelo.

## Decisión
Se adopta el diseño de alineación tal como está: `difflib.SequenceMatcher` por
tokens, con la limitación explícita sobre inserciones puras del gold, y comparación de
corrección por igualdad exacta de cadena (sin plegar tildes). Se agrega `--kappa-a`/
`--kappa-b` como subcomando del mismo módulo, no un archivo aparte, porque comparte
lectura de CSV y no justifica un módulo propio. `version_corrector()` lee
`procesar.py` con regex en vez de importar el módulo, documentado arriba con el
tiempo medido (5,44 s).
