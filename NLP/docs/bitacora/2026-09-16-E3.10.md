## Hallazgo: la URL del manifiesto apuntaba al lugar equivocado

El manifiesto registraba `https://github.com/PlanTL-GOB-ES/MeSpEn_Glossaries/archive/
refs/heads/master.zip` como fuente. Se descargó (permitido por `ALLOWED_DOMINIOS`,
prefijo `/PlanTL-GOB-ES/`):
```
cd C:\Users\ad6708\Documents\puebas
PYTHONPATH=. PYTHONIOENCODING=utf-8 .venv\Scripts\python.exe -m NLP.recursos.descargar --solo MeSpEn_Glossaries
```
Salida: `[MeSpEn_Glossaries] sha256=8032cbfe58bf8ddc06366b8d2fa4240fcda37accf832059d17b8bff43e5ebd4f
tamano_bytes=2026`. **2.026 bytes** es sospechosamente pequeño para un repositorio que
la propia API de GitHub reporta en 11.783 KB. Se listó el ZIP:
```
MeSpEn_Glossaries-master/           (directorio)
MeSpEn_Glossaries-master/LICENSE    646 bytes
MeSpEn_Glossaries-master/README.md  2.530 bytes
```
**El repositorio de GitHub solo contiene LICENSE y README.md**, comprobado también
contra la API (`api.github.com/repos/PlanTL-GOB-ES/MeSpEn_Glossaries/contents/`, dos
entradas, mismo resultado; `size: 11783` es el tamaño del historial de git, no del
árbol actual). El propio README lo confirma en su primera línea:
```
## Digital Object Identifier (DOI) and access to dataset files
https://doi.org/10.5281/zenodo.2205690
```
Los 46 glosarios (125.645 pares inglés-español) **nunca estuvieron versionados en el
repositorio de git**: solo en el depósito de Zenodo. La URL del manifiesto era, por
tanto, estructuralmente incapaz de traer los datos, con independencia de que Zenodo
respondiera o no. Se corrigió `recursos_manifiesto.json`:
`url` → `https://zenodo.org/api/records/2205690/files-archive`, `fuente_oficial`
documentando el hallazgo.

## Intento con la URL corregida: Zenodo tampoco respondió hoy

```
curl -s -o mespen_record.json -w "HTTP %{http_code}" --max-time 40 "https://zenodo.org/api/records/2205690"
```
Salida: `HTTP 504` (repetido dos veces). Mismo patrón que SympTEMIST y MedProcNER el
mismo día (ver `bitacora/2026-09-16-E3.4.md`): Zenodo respondió para DISTEMIST
(registro 6458115) en la misma franja horaria pero no para estos otros tres registros.
No se pudo, por tanto, ni confirmar el nombre exacto del archivo a descargar
(`archivos_extraer` queda sin fijar) ni descargar los datos.

## Consecuencia: no hay dato que medir, y por tanto no se integra

La ficha exige medir la ganancia marginal contra `pares_juzgados.csv` y
`limpio.csv` antes de decidir integrar (criterio explícito: "si no sube ≥ 0,5 puntos,
se documenta y no se integra"). **Sin poder descargar el recurso no hay columna
española que medir**: no se puede evaluar el criterio, ni a favor ni en contra. Esto es
distinto de un descarte por contenido (como el resto de la ficha contempla) — es un
bloqueo de disponibilidad, documentado con la misma evidencia y el mismo estándar que
E3.4.

**No se integra.** Es la decisión correcta con la información disponible hoy: no hay
manera de justificar activar una fuente nueva sin medirla (principio 1 del plan,
"evidencia antes que criterio"), y forzar una integración sin poder medirla habría
sido peor que no integrarla.
